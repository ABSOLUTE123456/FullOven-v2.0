# Отчёт ЛР19 — роли и доступ

## Что было сделано
- В объектную конфигурацию `config.json` добавлено глобальное поле управления доступа `Role` (User/Admin).
- Разработан статический модуль авторизации `Security/AccessControl.cs` для жесткой проверки системных привилегий.
- Логика переключения ролей полностью интегрирована со стандартной веб-формой авторизации сайта (`/Home/Login`):
  - При входе под системной учётной записью `admin` приложение автоматически переводит конфигурацию системы в режим `Admin` и предоставляет полный доступ.
  - При входе под любым другим пользователем или при нажатии кнопки `Выйти` (`Logout`), система автоматически сбрасывает права до уровня `User`.
- Наложены строгие инфраструктурные ограничения на выполнение административных операций:
  - Просмотр списка заказов (`AdminReservations`) — отказ и редирект для обычных пользователей.
  - Удаление бронирований (`DeleteReservation`) — отказ для обычных пользователей.
  - Изменение конфигурационных файлов (`Settings`) — отказ для обычных пользователей.

## Как проверить
1) Авторизоваться на сайте под обычной учетной записью (или выйти из аккаунта). Попытаться вручную открыть вкладки "заказы" или "настройки". Произойдет автоматический редирект на главную страницу с выводом ошибки "Недостаточно прав. Требуется роль: Admin".
2) Авторизоваться на сайте под зарезервированным логином `admin`. Убедиться, что блокировка автоматически снимается, а страницы управления и настройки конфигурации становятся полностью доступны.
